# 验证链路说明

## C 代码验证的是哪一步
这条 `host_gcc_validation` 验证链，验证的是 `Algorithm.c` 里这一步：

已知目标颜色 `xyY`，在固定白点和固定交点三角形下，把目标颜色分解成：

- 白点分量 `xyY`
- 交点分量 `xyY`
- `λ`
- 射线参数 `t`

对应到算法里的核心步骤是：

- `__algoLedFixCIE(25)`
  - 先得到 25°C 下当前使用的 LED 色域

- `__algoSplitTargetColorByWhite(...)`
  - 从白点出发找交点
  - 计算 `λ`
  - 计算白点分量和交点分量

## 这一步的输入是什么
当前验证使用的输入是固定的：

- 温度：`25°C`
- 白点：`(0.3090, 0.3176)`
- 固定交点三角形
- 30 个目标颜色 `xyY`

也就是说，验证时每次输入的是一个目标 `xyY`，算法去算它的分解结果。

## 这一步的输出是什么
对每个目标颜色，C 代码会输出这些结果：

- 目标颜色 `target_x / target_y / target_Y`
- 白点分量 `white_x / white_y / white_Y`
- 交点分量 `point_x / point_y / point_Y`
- 是否分解成功 `valid`
- 相交边编号 `edge_index`
- `λ`
- `1-λ`
- 射线参数 `t`

## 输出的 csv 是什么
C 代码最后生成的 `algorithm_validation_output.csv`，每一行对应一个目标颜色。

主要字段含义如下：

- `target_x10000, target_y10000, target_Y10000`
  - 输入的目标颜色 `xyY`

- `white_x10000, white_y10000, white_Y10000`
  - 算出来的白点分量 `xyY`

- `point_x10000, point_y10000, point_Y10000`
  - 算出来的交点分量 `xyY`

- `valid`
  - 这次分解是否成功

- `edge_index`
  - 交点落在哪条边上

- `lambda_fix16`
  - `λ`

- `one_minus_lambda_fix16`
  - `1-λ`

- `ray_t_fix16`
  - 射线参数 `t`

其中：

- `x / y / Y` 是乘 `10000` 的整数
- `lambda_fix16 / one_minus_lambda_fix16 / ray_t_fix16` 是 `fix16` 格式

## MATLAB 这边怎么验证
MATLAB 文件：

- [compare_host_csv.m](</e:/AUDI_COLOR/RGB/c_validation/compare_host_csv.m>)

它做的事情很直接：

1. 读取 C 输出的 csv
2. MATLAB 按同样的白点、同样的交点三角形、同样的目标颜色，再算一遍
3. 把两边的结果逐项比较

比较的就是：

- 白点分量
- 交点分量
- `λ`
- `t`

一句话概括：

> 看 `Algorithm.c` 里“白点 + 交点分解”这一步，和 MATLAB 仿真结果是否一致。
